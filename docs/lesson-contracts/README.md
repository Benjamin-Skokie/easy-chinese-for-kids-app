# Lesson Contracts

Keep one short contract for every visible learning topic, including completed pages. Create it before implementation and keep the same file as the maintained cross-book coverage ledger and decision record. It is not a second textbook audit or a narrative plan.

Organize contracts by the app's learning category:

| Category | Directory |
| --- | --- |
| Foundations | `foundations/` |
| Me & Family | `family/` |
| School Life | `school-life/` |
| Food | `food/` |
| World Around Us | `world/` |
| Play & Hobbies | `play-hobbies/` |

Keep only confirmed language, cross-book progression, unresolved source gaps, section ownership, approved asset/scene choices, and the remaining practice goal. Trace each confirmed requirement to a scene, Book words, Useful note, or practice; a sentence does not need its own picture when another surface covers it clearly. Update the same contract after implementation; remove rejected or resolved proposals rather than accumulating history.

For a completed topic, record the page's current layer, the later book layers that belong on the same page, and any deliberate scope boundaries. Use [../lesson_page_workflow.md](../lesson_page_workflow.md) for the build order. Move a contract out of this folder only when the topic is removed from the product.
