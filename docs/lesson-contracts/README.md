# Lesson Contracts

Use one short contract per topic under active content development. Create it before implementation. It is the coverage ledger and working decision record, not a second textbook audit or a narrative plan.

Organize contracts by the app's learning category:

| Category | Directory |
| --- | --- |
| Foundations | `foundations/` |
| Me & Family | `family/` |
| School Life | `school-life/` |
| Food | `food/` |
| World Around Us | `world/` |
| Play & Hobbies | `play-hobbies/` |

Keep only confirmed language, unresolved source gaps, section ownership, approved asset/scene choices, and the remaining practice goal. Trace each confirmed requirement to a scene, Book words, Useful note, or practice; a sentence does not need its own picture when another surface covers it clearly. Update the same contract after implementation; remove rejected or resolved proposals rather than accumulating history.

Use [../lesson_page_workflow.md](../lesson_page_workflow.md) for the build order. Move a contract out of this folder only when it no longer describes active or maintainable product behavior.
